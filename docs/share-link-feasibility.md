# 朋友分享飞机后对比：可行性验证

2026-10-28。结论：现有静态网站可以支持“分享飞机设计 → 接收者重新计算 → 与自己的飞机对比”，第一版无需新增服务器或账号系统。

当前只完成技术验证，游戏尚未加载实验模块，也没有分享或接收入口。

## 已运行的验证

运行 `node tests/share-link-feasibility.cjs`。协议原型在 `experiments/share-link-codec.js`，使用浏览器标准的 URL、UTF-8 与 Base64 API。

| 验证项 | 结果 |
| --- | --- |
| 六项参数、左右剪裁及浮点系数经链接往返 | 完整还原，三维面片一致 |
| 接收端重新模拟 | 与发送端的轨迹、距离、时间、高度一致 |
| 两个独立 JavaScript 上下文计算 | 距离一致，不依赖共享浏览器存储 |
| 无剪裁 / 12 条 / 30 条剪线示例 | 完整链接分别为 168 / 456 / 842 个字符 |
| 不同飞行参数的对比示例 | 7.858977… m 与 8.827859… m，可形成距离差 |
| 非法参数、退化剪线、未知模型、过长链接、伪造分数字段 | 拒绝解析 |
| 仅修改机身高度、张开角、上下折角和剪裁 | 外形变化，距离保持一致，符合当前模型边界 |

长度数据来自测试中的具体示例。复杂剪线的完整浮点系数可能生成更长的链接，正式版本应提示超长并提供设计文件导出等替代方式。原型限制编码片段不超过 8192 个字符、剪线不超过 100 条，超限时直接报错，不截断设计。

## 建议接入流程

1. 玩家确认飞机后，填写昵称并生成设计快照链接。快照携带格式版本、飞行模型版本、参数与剪线，不携带可信分数。
2. 朋友打开后，先显示分享者与飞机预览。将朋友设计放在独立的对比状态中，保留接收者当前飞机和本地历史。
3. 接收者确认后，用相同模型、无风与固定投掷条件分别重算两架飞机。沿用现有轨迹绘制，增加具名的两条轨迹及距离、滞空时间、最高高度对比。
4. 以界面显示的 0.1 m 精度判断距离相同；保留继续编辑、试飞与历史恢复。

## 正式上线前仍需完成

- 分享、复制失败时的手动复制、接收确认、错误恢复与具名对比界面。
- 导入时复用每次剪裁的连接与面积保护校验；当前原型已做格式与数值校验，不代表任意输入都是可折叠或合法的剪裁形状。
- 模型版本不同时明确提示不能直接比较，避免新旧算法混比分。
- 实测手机浏览器及常用聊天软件的链接转发、打开和复制。当前独立上下文测试使用 Node.js/V8，不等于不同浏览器引擎或物理手机验证。
- 昵称只作为显示名称，不代表认证身份。本机复算可以拒绝传来的伪造分数，但不能提供权威排行或完整防作弊保证。

飞行仍是未校准的简化模拟。目前只有机头、机翼比例和翼尾微调参与飞行计算；剪裁与其他折角的外观差异可能同分。玩家对比应明确为当前模拟条件下的结果，不能解释成真实纸飞机的性能排序。
